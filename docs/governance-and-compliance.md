# Governance & Compliance — dictum-binder

> One-line: MIT outbound; MIT-only inbound over every declared package and its transitive tree, enforced in CI by an own standard-library script; the interpreter, pip, and build backend exempt as infrastructure; contributions under MIT with nothing more; and — because the code is model-authored — a `SOURCE:`-marker discipline plus an LLM-driven detection pass whose residual is recorded before the first release.

## Purpose & Scope

Owns the licence and IP posture at the dependency boundary (`license-ip-compliance`) and the first-party source-provenance register (`source-provenance`). Compliance policies carry the `POLICY-*` prefix per the spec even though none concerns data handling: there is no classified data, so the canonical `POLICY-per-tag` case is empty by trait fact.

## Non-goals / Out-of-scope

- `data-handling-policy` — `absent`: no classified data (Domain scoped tags out).
- `audit-requirements` — `absent`: single-user local tool; no accountability regime, no audit trail.
- `compliance-framework-mapping` — `absent`: not regulated; no framework obligations apply.
- `records-retention-data-residency` — `absent`: no records held.
- `consent-management` — `absent`: no personal data.
- No CLA and no DCO sign-off: contributions are accepted under MIT by the act of submission. `absent` by decision.
- No automated copy scanner: test and tooling dependencies are strictly MIT, which excludes the common scanners; the detection pass is LLM-driven and recorded. `absent` by decision.
- The **interpreter (PSF-2.0), pip, and the build backend (setuptools, which vendors `packaging`)** are environment infrastructure, not declared dependencies, and sit outside the inbound rule; applied to them the rule is unsatisfiable for any Python project. `absent` by the operator's scope decision (2026-09-17).

## Requirements

### License & IP compliance (the dependency boundary)

- **Outbound stance**: MIT, the entire terms of use (`POLICY-OUTBOUND-MIT`). The `LICENSE` file at the repository root is the MIT text with the operator as copyright holder.
- **Inbound allowlist**: **MIT only**, for every package the project *declares* — runtime and development — and everything those resolve to transitively (`POLICY-INBOUND-MIT-ONLY`). **Scope**: the interpreter, pip, and the build backend are environment infrastructure and exempt. Enforced on every CI run by an own script, `tools/licence_gate.py`, standard library only (`importlib.metadata` over the resolved environment): any distribution whose `License-Expression`, `License` field, or licence classifier is not exactly MIT fails the gate; a distribution with ambiguous or missing licence metadata fails too. The fix is to pin a version with correct metadata or drop the package, never to allowlist by hand.
- **Inbound register** (verified against PyPI metadata on 2026-09-17): runtime — ruamel.yaml 0.19 (MIT, zero required dependencies). Development — ruff (MIT, zero dependencies), pyrefly (MIT, zero dependencies), registered as `TOOL-RUFF`/`TOOL-PYREFLY` in Operations but still declared Python dependencies under this rule. Everything else in the toolchain is the standard library or own code. **Rejected under the rule**, with the offending package: jsonschema (`typing_extensions`, PSF-2.0, via `referencing` on Python < 3.13), pytest (`packaging`, Apache-2.0 OR BSD-2-Clause; `pygments`, BSD-2-Clause), mypy (`typing_extensions`; `pathspec`, MPL-2.0), coverage.py (Apache-2.0 itself), slipcover and covers (Apache-2.0), pip-licenses (`prettytable`, BSD-3-Clause). The register is regenerated by the gate; this list is the scaffold-time snapshot.
- **Vendored material**: `dictum/` is a local cache of the Dictum standard, prose CC BY 4.0 and templates MIT, attribution to David H. Jung and the Dictum contributors, kept verbatim with its `LICENSE` and `LICENSES/`; the README carries one attribution line. It is not product code and is not imported by the tool.
- **Contributions**: accepted under MIT by submission; no CLA, no DCO (`POLICY-CONTRIBUTIONS-MIT`).

### Source provenance (first-party)

- Code is **model-authored** (`code_authorship: model-authored`), so provenance is undeclared by default and the stronger bar applies.
- **Attestation at the site**: `POLICY-SOURCE-MARKER` requires every non-trivial first-party unit copied, ported, adapted, or transliterated from any external source to carry `# SOURCE: <origin> — <license>` in a comment at the site. `[REVISIT]` This is the ` — ` separator form of the pending Dictum v1.3.0; the vendored v1.2.0 text fixes the space-separated `SOURCE: <origin> <license>`. Adopted now because it tokenises unambiguously and the tool ships against v1.3.0; the upgrade walk tied to Product's v1.3.0 `[REVISIT]` confirms or reverts it. `<license>` is an SPDX identifier or `proprietary` / `non-redistributable` / `unknown`. A unit marked with any licence other than MIT is a **defect**, not a smell, and blocks the release gate until removed or rewritten.
- **Detection pass**: `POLICY-PROVENANCE-PASS` requires, before the release tag, an LLM-driven review, module by module over `src/lspd/`, `tests/`, and `tools/`, that (1) lists every non-trivial unit (a function, class, or fixture longer than a few lines); (2) states for each whether it was written fresh, adapted from documentation examples, or resembles known code; (3) searches distinctive fragments — unusual identifiers, error strings, regexes, algorithms — against public sources; (4) records each determination in the *Provenance register* — whose **shape** is contracted below and whose **rows** live in the Delivery-owned build-status record `docs/IMPLEMENTATION.md`, because filling them is an implementation-time act that must not edit a published doc; and (5) records the **residual** honestly: which units could not be checked and why. The residual is never read as "cleared".
- **Gate**: a fitness test asserts every `SOURCE:` marker in the tree parses to the token form and names `MIT`; the release-gate checklist (Delivery) requires the pass to be recorded in `docs/IMPLEMENTATION.md` (never in this published doc).

## Examples / Worked scenarios

1. **A dependency bump.** ruamel.yaml's new version pulls a transitive package under BSD-3-Clause. CI's licence-gate step fails; the implementer pins the previous version and records why in the commit. No hand allowlisting.
2. **A rule written from a specification.** The emitter's YAML-quoting decision implements the YAML 1.2 specification's plain-scalar rules. A specification's prose is not code, so the unit carries no `SOURCE:` marker; the provenance pass records it as "written from the spec, no copied code". Only copied or adapted *code* is marked.
3. **The pass finds a match.** A helper resembles a Stack Overflow answer (CC BY-SA 4.0). It is a defect: the unit is rewritten from scratch, the pass re-run on it, and the register row updated. The residual note records that the match was found by fragment search, not by recall.

## Design Decisions

| Decision | Rationale |
|---|---|
| MIT only, enforced over the whole declared tree in CI, infrastructure exempt | The operator's rule; automated so a transitive change cannot slip through; the exemption is the minimum that keeps the rule satisfiable for a Python project |
| No CLA, no DCO | A small MIT project; submission under the same terms is the default and adds no friction |
| `SOURCE:` separator form from v1.3.0 | The tool ships against v1.3.0; the older form tokenises ambiguously |
| LLM-driven detection pass | Scanners are excluded by the MIT-only rule; the pass is best-effort by the standard's own admission and its residual is recorded rather than hidden |

## Acceptance criteria

1. A CI step runs `tools/licence_gate.py` over the resolved environment and fails on any distribution whose licence is not exactly MIT (`POLICY-INBOUND-MIT-ONLY`); a unit test feeds the script a fake distribution with a BSD licence and one with no licence metadata and asserts both fail.
2. A fitness test parses every `SOURCE:` comment in the tree against the token form `SOURCE: <origin> — <license>` and fails on a malformed marker or a licence other than `MIT` (`POLICY-SOURCE-MARKER`).
3. `docs/IMPLEMENTATION.md` contains the filled provenance register in the contracted shape and a non-empty residual paragraph, and its release-gate checklist references that section (`POLICY-PROVENANCE-PASS`).
4. `LICENSE` at the root is the MIT text; the README names MIT, the contribution terms, and the Dictum attribution line (`POLICY-OUTBOUND-MIT`, `POLICY-CONTRIBUTIONS-MIT`).
5. The naming fitness test in Quality exists and checks all four clauses of `LEGAL-DICTUM-NAMING` (`POLICY-NAMING-ENFORCEMENT`).
