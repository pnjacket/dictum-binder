# Governance & Compliance — dictum-binder

> One-line: MIT outbound, MIT-only inbound enforced in CI over the full dependency tree, contributions under MIT with nothing more, and — because the code is model-authored — a `SOURCE:`-marker discipline plus an LLM-driven detection pass whose residual is recorded before the first release.

## Purpose & Scope

Owns the licence and IP posture at the dependency boundary (`license-ip-compliance`) and the first-party source-provenance register (`source-provenance`). Compliance policies carry the `POLICY-*` prefix per the spec even though none concerns data handling: there is no classified data, so the canonical `POLICY-per-tag` case is empty by trait fact.

## Non-goals / Out-of-scope

- `data-handling-policy` — `absent`: no classified data (Domain scoped tags out).
- `audit-requirements` — `absent`: single-user local tool; no accountability regime, no audit trail.
- `compliance-framework-mapping` — `absent`: not regulated; no framework obligations apply.
- `records-retention-data-residency` — `absent`: no records held.
- `consent-management` — `absent`: no personal data.
- No CLA and no DCO sign-off: contributions are accepted under MIT by the act of submission. `absent` by decision.
- No automated copy scanner: test and tooling dependencies are strictly MIT, which excludes the common scanners; the detection pass is LLM-driven and recorded. `absent` by decision.

## Requirements

### License & IP compliance (the dependency boundary)

- **Outbound stance**: MIT, the entire terms of use (`POLICY-OUTBOUND-MIT`). The `LICENSE` file at the repository root is the MIT text with the operator as copyright holder.
- **Inbound allowlist**: **MIT only**, for runtime dependencies, their full transitive tree, and every development or test dependency (`POLICY-INBOUND-MIT-ONLY`). Enforced on every CI run by `pip-licenses` (MIT) over the resolved environment; any package whose declared licence is not MIT fails the gate. A package with an ambiguous or missing licence metadata field fails too; the fix is to pin a version with correct metadata or drop the package, never to allowlist by hand.
- **Inbound register** (current, at scaffold): ruamel.yaml (MIT) and its `ruamel.yaml.clib` (MIT); jsonschema (MIT) with attrs (MIT), rpds-py (MIT), referencing (MIT), jsonschema-specifications (MIT); dev: pytest (MIT), coverage (Apache-2.0 — **not MIT; see open question**), ruff (MIT), mypy (MIT), pip-licenses (MIT). The register is regenerated by the gate; this list is the scaffold-time snapshot.
- **Vendored material**: `dictum/` is a local cache of the Dictum standard, prose CC BY 4.0 and templates MIT, attribution to David H. Jung and the Dictum contributors, kept verbatim with its `LICENSE` and `LICENSES/`; the README carries one attribution line. It is not product code and is not imported by the tool.
- **Contributions**: accepted under MIT by submission; no CLA, no DCO (`POLICY-CONTRIBUTIONS-MIT`).

### Source provenance (first-party)

- Code is **model-authored** (`code_authorship: model-authored`), so provenance is undeclared by default and the stronger bar applies.
- **Attestation at the site** (`POLICY-SOURCE-MARKER`): every non-trivial first-party unit copied, ported, adapted, or transliterated from any external source carries `# SOURCE: <origin> — <license>` in a comment at the site, using the v1.3.0 separator form (the vendored v1.2.0 text shows the older space-separated form; the separator form is adopted now because it tokenises unambiguously and is what the tool will ship against). `<license>` is an SPDX identifier or `proprietary` / `non-redistributable` / `unknown`. A unit marked with any licence other than MIT is a **defect**, not a smell, and blocks the release gate until removed or rewritten.
- **Detection pass** (`POLICY-PROVENANCE-PASS`): before the release tag, an LLM-driven review, module by module over `src/lspd/` and `tests/`, that (1) lists every non-trivial unit (a function, class, or fixture longer than a few lines); (2) states for each whether it was written fresh, adapted from documentation examples, or resembles known code; (3) searches distinctive fragments — unusual identifiers, error strings, regexes, algorithms — against public sources; (4) records each determination in the *Provenance register* below; and (5) records the **residual** honestly: which units could not be checked and why. The residual is never read as "cleared".
- **Gate**: a fitness test asserts every `SOURCE:` marker in the tree parses to the token form and names `MIT`; the release-gate checklist (Delivery) requires the pass to be recorded in this doc.

## Open Questions

- `[GAP]` `coverage.py` is licensed Apache-2.0, not MIT, and Quality's 100 % coverage gate depends on it. Under `POLICY-INBOUND-MIT-ONLY` it cannot be installed. Options: (a) allow Apache-2.0 for development-only tooling as a named exception; (b) measure coverage another way; (c) drop the numeric gate. The operator's "MIT only" was stated before this dependency was noticed; it needs a decision. Until then the coverage gate in Quality is blocked-by-policy.

## Examples / Worked scenarios

1. **A dependency bump.** ruamel.yaml's new version pulls a transitive package under BSD-3-Clause. CI's `pip-licenses` step fails; the implementer pins the previous version and records why in the commit. No hand allowlisting.
2. **An adapted snippet.** The emitter's YAML-quoting decision is adapted from the YAML 1.2 specification's plain-scalar rules. The site carries `# SOURCE: YAML 1.2 spec §7.3.3 — unknown`? No: a specification's text is not code; the rule is re-implemented from the description and carries no marker. The provenance pass records the unit as "written from the spec, no copied code".
3. **The pass finds a match.** A helper resembles a Stack Overflow answer (CC BY-SA 4.0). It is a defect: the unit is rewritten from scratch, the pass re-run on it, and the register row updated. The residual note records that the match was found by fragment search, not by recall.

## Design Decisions

| Decision | Rationale |
|---|---|
| MIT only, enforced over the whole tree in CI | The operator's rule; automated so a transitive change cannot slip through |
| No CLA, no DCO | A small MIT project; submission under the same terms is the default and adds no friction |
| `SOURCE:` separator form from v1.3.0 | The tool ships against v1.3.0; the older form tokenises ambiguously |
| LLM-driven detection pass | Scanners are excluded by the MIT-only rule; the pass is best-effort by the standard's own admission and its residual is recorded rather than hidden |

## Acceptance criteria

1. A CI step runs `pip-licenses` over the resolved environment and fails on any package whose licence is not exactly MIT (`POLICY-INBOUND-MIT-ONLY`); a fixture environment with one BSD package proves the failure path.
2. A fitness test parses every `SOURCE:` comment in the tree against the token form `SOURCE: <origin> — <license>` and fails on a malformed marker or a licence other than `MIT` (`POLICY-SOURCE-MARKER`).
3. The release-gate checklist in `docs/IMPLEMENTATION.md` links to the filled provenance register and its non-empty residual paragraph (`POLICY-PROVENANCE-PASS`).
4. `LICENSE` at the root is the MIT text; the README names MIT, the contribution terms, and the Dictum attribution line (`POLICY-OUTBOUND-MIT`, `POLICY-CONTRIBUTIONS-MIT`).
